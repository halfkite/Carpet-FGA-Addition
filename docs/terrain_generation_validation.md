# 地形任务与虚空生成验收

本轮基线为 Minecraft 26.3，共享生命周期、地图票据与虚空行为覆盖 1.21.1、1.21.3、1.21.4、1.21.5、1.21.8、1.21.10、1.21.11、26.1.2、26.2、26.3

所有操作只在可丢弃的测试存档执行；先备份测试存档，不使用生产世界

## 代码验证

使用 Gradle Wrapper 执行各版本 `:<版本>:build`，不跳过现有测试

- `TerrainRegenerationLifecycleTest`：关闭世界清空惰性标记、完成后清理队列与未完成清空任务，新世界不会沿用旧状态
- `MapLoadReleaseLifecycleTest`：无活动任务时仍按 32/tick 回收，暂不可回收的条目保留到后续 Tick
- `TerrainGenerationMixinTargetTest`：按实际游戏类检查地形、装饰、超平坦与重生成方法签名，检查处理后的 Mixin 资源仍为 required 且完整注册

这些单元测试不替代实际区块生成、整合包和客户端验收

## 1：同一客户端进程切换世界

1. 在测试世界 A 创建 `/regenerateTerrain create from 4096 4096 4111 4111`，从预览确认任务，但不要加载目标区块
2. 退出到主菜单，不重启客户端；进入相同维度的测试世界 B，其目标区块事先放有已保存的标记方块
3. 加载 B 的目标区块，检查标记方块仍在，`/regenerateTerrain list` 不包含 A 的任务
4. 另用 A 创建并确认较大的 `clear` 任务，执行途中退出；再次进入 B，检查相同范围的方块、实体与 POI 未被清空，未出现 A 的进度条

验收：旧标记、清理队列和执行中的清空任务均不作用于 B

## 4：最后一个地图加载任务的票据回收

1. 手持已创建的地图，执行 `/mapLoad start fast`，等待目标区块开始加载
2. 执行 `/mapLoad stop`，确保 `/mapLoad list` 已无任务，不再启动新的加载任务
3. 让测试玩家离开这些区块，通过服务端调试器或票据监视工具观察 FGA 地图票据数量，等待生成完成及正常卸载周期
4. 分别验证正常完成、玩家断开、切换维度、暂停后终止；重复 start/stop，确认票据不累积

验收：无活动任务时仍继续回收，FULL 区块或超过 10 秒仍未完成的票据按原限速释放；普通玩家和其他系统的票据不被移除

## 5：26.3 已有区块重生成

1. 在测试区块放置标记方块，保存后离开足够远，确保区块卸载且不受 forceload 等票据保留
2. 从区块外创建覆盖该区块的 `create from` 任务并确认，保持原权限和预览确认流程
3. 返回目标区块，检查标记消失且地形重新生成；启用虚空规则时重复，目标区块仍应按正常地形生成
4. 离开、保存并重载，确认同一区块不反复重生成；检查相同坐标的其他维度不受影响

验收：确认代表已添加惰性标记，实际重生成发生于下次加载，生成完成后标记被消耗

## 虚空世界保留结构本身的数据

1. 以固定种子创建普通、超平坦测试世界，启用世界的结构生成选项，在进入新区域前执行 `/carpet voidWorldGeneration true`
2. 在普通世界使用 `/locate structure minecraft:fortress`、`minecraft:monument` 等合适维度的结构，在超平坦世界使用村庄；选择尚未生成的目标范围并加载
3. 保存后检查区块 NBT：所有 section 的方块状态为空气；没有结构建筑、地层、矿石、植被、流体或方块实体；群系数据保留
4. 检查结构起点、有效结构分块及其范围、相邻区块引用仍存在，结构定位仍可用；重新加载后再次检查
5. 在具备对应刷怪条件的人工测试平台上，验证结构相关刷怪判定；测试平台是玩家放置的方块，不属于地形生成
6. 关闭规则后进入新区域，确认原版地形与结构方块恢复；已有区块和玩家放置方块不因切换规则被删除
7. 在虚空模式下确认 `create` 重生成任务只恢复指定范围，未标记的新区块仍为空气

验收：保留结构起点、引用和范围，不放置构成结构的方块；定位成功不能单独代替结构数据检查

世界首次初始化的出生点布置、末地传送平台、玩家放置、实体行为及其他模组主动写入方块属于后续世界修改，需与本规则的新区块生成区分；本轮不删除这些方块或既有存档内容
